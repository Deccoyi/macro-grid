# Changelog (developer)

This file follows the [Keep a Changelog](https://keepachangelog.com/) format. For versioning rules, see [versioning.md](versioning.md). The short, public changelog is [CHANGELOG.md](CHANGELOG.md).

## [Unreleased]
### Added
- **Automatic profile switching based on the active window (opt-in):** see `docs/design/auto-profile-switch.md`. `AppMatches` (process name + optional title filter) was added to the profile model. `MacroStation.Windows.ForegroundWindowMonitor` (`SetWinEventHook(EVENT_SYSTEM_FOREGROUND)`, event-driven, no polling) and `AutoProfileSwitcher` in Core (`IHostedService`) drive each session's own stack-based `AutoSwitchState`. When a defined window comes to the foreground, the session switches to that profile. When an undefined window gains focus (focus loss) or the app closes, it returns to the manually chosen profile. If the stack runs empty, `ProfileResolver.ResolveDefault` takes over (device assignment → `AppPreferences.DefaultProfileId` → first profile). Each device opts in with `PairedDevice.FollowActiveWindow`. The drawer lock (`PairedDevice.AutoSwitchLocked`, new `profile.lock` message) pauses auto-switching but leaves manual switching available. New endpoints: `GET /api/system/windows`, `PUT /api/devices/{id}/follow-window`. `profiles.list` now carries `autoSwitch: {enabled, locked}`. Editor: a rule list opened by a window icon in the profile panel (pick from running apps or type an exe name), a per-device "Follow active window" switch in Pairing, and a default-profile picker under the "Profiles" category in Preferences. The stack, lock and default logic of `AutoSwitchState` is covered by unit tests (`AutoSwitchStateTests`); verified end to end with real OS foreground events (rule window ↔ another window). The drawer lock is now a switch with a lock icon.
- **A failed widget action is now a visible warning:** it used to be written only to the server log file (for example a button bound to a deleted OBS scene). `ActionDispatcher.DispatchAsync` now collects error messages and `ClientHub` forwards them to two places: the editor status bar as a `core.actionError` warning (`StatusBar.tsx` is already generic, so no extra code was needed), and the device that triggered the action as an `error`/`action_failed` envelope, shown in both the web/browser client (`webclient/`, red toast, 4 s) and the real Android app (`macro-station-client`, same toast pattern). Verified end to end with real OBS and a real device (USB `adb`).
- **Plugin uninstall:** `DELETE /api/plugins/{id}` (`ServerApp.cs`) deletes the `%AppData%/MacroStation/plugins/<id>/` folder. The plugin is unloaded first (see "Plugin hot loading" below); if a file is still in use anyway, an `.uninstall` marker file is left and `PluginManager` deletes marked folders on the next start before loading anything. A Remove button (`PluginsWindow.tsx`, `Trash2` icon) was added to each row of the editor's "Plugins" window. Because it is destructive, it asks for confirmation through `confirmAsync` (the app-styled confirm in `dialogStore.ts`, not the native `confirm()`).

- **JS plugin runtime (`docs/design/js-plugin-runtime.md`):** `kind: "js"` plugins run in a Jint sandbox. `JsPlugin` (`Core/Plugins/Js`) implements `IPlugin`, so it goes through the same `PluginManager` pipeline as a C# plugin (registrations, hot load, unload, uninstall); it runs on its own thread with a one-job-at-a-time queue and per-call limits (`JsPluginLimits`: 2 s, 32 MB, 2M statements, recursion 100, 20 timers, HTTP 5 s / 1 MB). The engine gets no CLR access; the script sees only a frozen `host` object built from delegates that the bootstrap script captures and removes from the global scope. Every host call checks the approved permissions (`JsPermissions`: `variables`, `actions`, `input`, `http:<host>:<port>`); variable names and action types must start with the plugin id; HTTP only to approved host:port, no redirects. Approvals are kept per plugin in `plugin-permissions.json` (`PluginPermissionStore`) and are for an exact set: a plugin that asks for more waits again (`PluginLoadStatus.NeedsApproval`, `LoadedPlugin.PendingPermissions`). New endpoint `POST /api/plugins/{id}/approve`; the editor's Plugins window lists the permissions and has an allow-and-enable button. A plugin that fails 5 times in a row is switched off (`PluginManager.DisableAsync`). `PluginManager` gained `ApproveAsync` and takes the permission store and `IInputService`; uninstall forgets the approval. `Jint 4.16.3` was added to `MacroStation.Core`. Example plugin: `macro-station-plugin/HelloJs/`. Tests: `JsPluginTests` (sandbox: no CLR, frozen host, namespaces, endless loop, memory, recursion, switch-off, timers, HTTP, input, settings) and JS cases in `PluginManagerTests`.
- **Release packaging (`docs/release.md`):** `scripts/publish.ps1` builds the editor and publishes a self-contained single-file `MacroStation.exe` (compressed, about 62 MB, with `wwwroot` beside it; version read from `ClientHub.ServerVersion`, WebView2 reference XML files removed) into `artifacts/server`. `installer/MacroStation.iss` and `installer/build-installer.ps1` wrap it in an Inno Setup installer: Start menu entry, optional desktop shortcut, optional per-user autostart, inbound firewall rule for TCP 9820 on private networks (removed on uninstall), running server closed before an upgrade, `%AppData%/MacroStation` kept on uninstall. The published exe was smoke-tested (starts, serves `/api/plugins` and the editor); the installer script itself was not compiled because Inno Setup is not installed on the development machine.
- **`.msprofile` export and import:** `ProfilePackage` (`Core/Profiles`) writes and reads a zip with `manifest.json` (format version, profile name, export time, server version, the plugins the profile's actions need with the action types used) and `profile.json`. Icons and images stay inside `profile.json` as the `data:` values the profile already holds, so a package is self-contained; there are no separate asset entries (yet no sounds exist either). Reading is defensive: only the two known entries are read, capped at 64 MB with the read itself bounded, the profile must pass `ProfileValidator`, a package with a newer `formatVersion` is refused with a clear message, and a plain profile JSON (the older export) is still accepted, just without a manifest. `POST /api/browse/export-profile` now takes the profile and writes a package; `POST /api/browse/import-profile` returns the profile plus `missingPlugins` (from the manifest, checked against loaded plugins by `PluginManager.MissingPlugins`) and `unknownActionTypes` (bound action types nothing provides). `IUiDialogService` open/save are now byte-based and take a file filter (`OpenFileAsync`, `SaveFileAsync`; the JSON-only versions were removed). The editor's File menu exports `.msprofile`, imports `.msprofile` or `.json`, shows the server's reason when a file is unusable and warns about missing plugins after an import. Tests: `ProfilePackageTests`, `PluginManagerTests`.
- **Widget text and icon dynamization:** `Widget.Dynamic["text"]` and `["style.icon"]` are now honored. `DynamicText` (`Core/Variables`) picks the text template (first matching case, else default, else the static text) and renders it, so a rule result may contain `{variables}`; `WidgetStateService` uses it for the initial push and for live updates (recomputed when a variable in the conditions or in any candidate template changes) and always pushes the text of a dynamized widget. `style.icon` was added to `DynamizableProperties`; the icon travels in the `widget.state` style, as an `asset:<hash>` reference for clients with the `assets` capability (`LayoutSender.ForClient`, `AssetStore.ExternalizeValue`). Editor: `DynamizeModal` gained the `"text"` and `"icon"` result kinds (the icon kind reuses `IconPicker`, baked with the widget's text color; an empty case result means no icon), `TextFields` got the lightning-bolt on the text and icon labels, and the canvas previews both (`evaluateWidgetDynamicText`). Both renderer copies accept `icon` in `liveStyle` / `WidgetState.style`. Tests: `DynamicTextTests`.
- **Plugin hot loading:** `PluginManager` (`Core/Plugins`, hosted service registered after `VariableProviderHost`) replaces the one-shot `PluginLoader`. Plugins are installed, reloaded (`POST /api/plugins/{id}/reload`) and uninstalled while the server runs; `POST /api/plugins/install` loads the plugin immediately and replaces an existing id (its own files such as `settings.json` are kept). Registrations are applied to now-dynamic registries (`ActionDispatcher.Register/Unregister`, `VariableCatalog.Add/Remove`, `VariableProviderHost.StartOwned/StopOwnerAsync`, `PluginStatusRegistry.RemovePlugin`) and taken back out on unload; variables a plugin set are removed through `TrackingVariableStore`; the plugin instance and everything it registered is disposed if it implements `IDisposable`/`IAsyncDisposable`. An action type clash fails the whole plugin and rolls back. Plugin assemblies are loaded from memory (`PluginLoadContext.LoadPluginAssembly`) so files are never locked (`Assembly.Location` is empty inside a plugin). The editor's Plugins window has reload and no longer asks for a restart; the main editor refetches actions, variable catalog and icon packs on window focus. Tests: `PluginManagerTests` (replaces `PluginLoaderTests`). See `docs/design/layout-patch-and-assets.md`.
- **`layout.patch`:** a saved edit reaches a client that announced the `layout.patch` capability as only the changed widgets (`LayoutDiff`, per-session baseline in `ClientSession.SentLayout`, `LayoutSender.SendUpdateAsync`); nothing is sent when nothing the client renders changed. `WidgetStateService.BroadcastProfileAsync` clears the sent-state cache only for the changed widgets and re-sends their live state. Other clients (the browser client) still get `layout.full`.
- **Cached assets:** with the `assets` capability, `data:` values of 200+ characters in a layout become `asset:<hash>` references (`AssetStore`, SHA-256 based, LRU); the client fetches missing ones with `asset.get` and gets `asset` replies. `hello` gained `capabilities` (`ClientCapabilities`). All layout sends go through `LayoutSender`. Tests: `LayoutDiffTests`, `AssetStoreTests`, `LayoutSenderTests`.

### Changed
- **The editor API is local only:** `/api` answers `403` to any request whose remote address is not loopback (`LoopbackGuard`, middleware in `ServerApp.cs`); it could otherwise read the pairing PIN, approve plugin permissions and change profiles from anywhere on the network. Phones and the browser deck only use `/ws`.
- **`{variables}` in action fields are resolved by the server:** `ActionDispatcher` renders the templates of every field a handler declares with `AllowVariables` before `ExecuteAsync` (on a copy, the saved binding is untouched). The SDK documented this but nothing did it. Tests: `ActionVariableTests`.
- New `GET /api/version` (`ClientHub.ServerVersion`); the editor's Help menu and window show it instead of a hard-coded number. The client and the browser deck now send their `package.json` version in `hello`.
- `@testing-library/dom` added to the renderer's dev dependencies (the renderer tests could not run on a fresh install without it).
- `scripts/publish.ps1` also builds the browser deck and ships `LICENSE` and `THIRD_PARTY_NOTICES.md`.
- Documentation rewritten in English for publishing: README, `docs/architecture.md`, `docs/development.md`, `docs/roadmap.md` (replace `plan.md` and `agent-notes.md`), `docs/design/` (was `docs/done/`), UI guidelines and color system; `CONTRIBUTING.md`, `SECURITY.md` and updated third-party notices added. Session handoff notes and the retired OBS draft were removed.
- `LayoutFullPayload` was removed; layouts are now sent as JSON nodes through `LayoutSender`.
- Slim, rounded scrollbar across the editor (`theme.css`); the track is transparent and the thumb only stands out on hover.

### Removed
- `PluginLoader` / `PluginLoadResult` (replaced by `PluginManager`).

### Fixed
- **Editor modals closed on drag:** a text selection that started inside a modal and ended outside was treated as a click on the backdrop and closed the window. It now closes only when both mousedown and mouseup land on the backdrop (`useBackdropClose`).

## [0.2.0] - 2026-09-23
### Added
- **Plugin SDK 0.3.0 — schema-based settings forms:** `SettingField`, `IActionDescriptor`, `IOptionsSource`, `IPluginSettingsPage`, `IPluginStatusItem`, `IIconPackSource`, `IVariableStore.Remove`. The editor automatically draws the form of a plugin action or settings page from `SettingField[]` (`SchemaForm.tsx`); dynamic dropdowns come through `IOptionsSource`.
- **Categorized action picker** (`ActionPicker.tsx`): replaces the plain `<select>`, grouped by category and searchable.
- **Window-wide status bar** (`StatusBar.tsx`, `PluginStatusRegistry`): server version and connected device count on the left, plugin statuses (for example the OBS connection) on the right; clicking one opens the plugin's settings window (`PluginSettingsWindow.tsx`).
- New endpoints: `GET /api/status`, `POST /api/actions/{type}/options/{sourceId}`, `GET /api/plugins/{id}/settings/schema`, `POST /api/plugins/{id}/settings/options/{sourceId}`, `POST /api/windows/plugin-settings/{id}`, `GET /api/icon-packs(/{packId}/{iconName})`. `GET /api/actions` now returns category/description/icon/fields, and `GET /api/plugins` returns `hasSettings`.
- The editor and tool windows now use the application icon.
- **Plugin icon packs:** besides Lucide, the icon picker also lists the packs plugins add with `IPluginHost.RegisterIconPack` as separate categories (including "All"). A stored icon name is looked up in Lucide first, then in plugin packs, and is tinted with the selected color. First pack: PLC Icons (`macro-station-plugins/PLCIcons/`).

### Changed
- The OBS-specific inline settings form (`ObsSettingsInline`) was removed; every plugin with settings uses the generic settings window.
- Action event cells are the same size in every widget type (always a 4-column grid).

### Fixed
- The color picker was left behind the "Build logic" window.
- The comparison value box in the logic editor was too narrow, and it was unclear whether text values should be quoted (they are written without quotes; there is now a hint).

### Added (earlier)
- **The last item of Stage 5 is closed: a USB debug test on a real device.** The `macro-station-client` Android project was installed on a real Android phone with `adb install` (debug APK). A previously paired device reconnected to the server over the real LAN. Live variable push (the volume widget's percentage/color changed instantly), touch input, and swipe correctly staying a no-op on a single-page profile were verified. (The `sdk.dir` in `android/local.properties` was broken by backslash escaping — in the Java `.properties` format `\` is an escape character; fixed.)
- **First real plugin: OBS Control** (`macro-station-plugins/OBS/`). It connects to obs-websocket v5 (Hello/Identify handshake, SHA256 authentication, automatic reconnect with capped exponential backoff). Variables `obs.connected/streaming/recording/stream.duration/record.duration/scene.current/stats.fps/stats.cpu`; actions for switching scenes, start/stop/toggle of streaming and recording, and input mute/unmute/level. Connection settings are kept in the plugin's own `%AppData%/MacroStation/plugins/obs/settings.json`. To make this possible, `IPluginHost` gained `DataDirectory` (the plugin's own folder) and `Log(string)`, and the Plugin SDK got a MINOR bump from `0.1.0` to `0.2.0` (members were added to an existing interface that plugins only consume, not implement — backward compatible).
- **Editor UI for plugin settings (OBS as the first example):** generic `GET`/`PUT /api/plugins/{id}/settings` endpoints on the host (they pass raw JSON to a plugin's own `settings.json`; the host knows no schema — the id is validated against path traversal). A gear button was added next to the OBS row in the editor's "Plugins" window; clicking it opens Enabled/Server/Port/Password fields and a Save button under the row (not a new window/modal, but an in-row expansion within the existing list — see `docs/ui-guidelines.md`). This form was OBS-specific code (`ObsSettingsInline`); the host had no generic settings schema/form generator. Also: `input[type="password"]` was missing from the base input style (it rendered white/with the browser default); added.
- **Plugin system — loader done (Stage 6):** `IPlugin`/`IPluginHost` (`MacroStation.Plugin.Abstractions`); each plugin loads in its own isolated `AssemblyLoadContext`; `plugin.json` manifest (compatibility check via a caret range on `sdkVersion` plus `minServerVersion`). `PluginLoader.LoadAll` scans `%AppData%/MacroStation/plugins/` on every server start. The editor's "Plugins" window now shows the real list and copies a plugin folder into place through the native "Load from folder…" dialog (`IUiDialogService.BrowseForFolderAsync`; a restart is needed for it to take effect). There is no JS/Jint runtime yet (Stage 7) — `kind:"js"` manifests are recognized but marked "Incompatible". No real plugin had been written yet; the plugin authoring guide is at `macro-station-plugins/docs/plugin-authoring.md`.
- **Per-device profile assignment:** each paired device can be assigned a profile from the Pairing window (`PairedDevice.AssignedProfileId`, `PUT /api/devices/{id}/profile`); an unassigned device falls back to the first profile when it connects.
- **Page navigation and profile switching from the client:** `page.next`/`page.prev` messages were added to the WebSocket; horizontal swipe changes pages in the phone/browser client. `profile.change` (which already existed) is triggered from the profile drawer.
- **Kiosk mode and orientation lock (Capacitor client):** native `KioskPlugin.java` (immersive/full screen) plus orientation lock with `@capacitor/screen-orientation`; a Settings panel was added inside the profile drawer, and the settings persist in `localStorage`.
- **Master volume added as a built-in action/variable:** `IAudioService`/`WindowsAudioService` (NAudio CoreAudioApi), `system.audio.master`/`system.audio.muted` variables (1 s poll), `core.setVolume`/`core.setMute`/`core.toggleMute` actions. In the editor, slider/knob widgets gained two-way binding to a variable (`valueVariable`) and a "Value changed" (`valueChange`) action event.
- **Browser client:** the new `webclient/` (Vite+React+TS) is served by the server under `/deck/` (`app.UseStaticFiles()`) and connects to the same origin automatically without typing an IP. A link was added to the Pairing window.
- **OBS API research and preparation for the plugin system design:** the obs-websocket v5 protocol was researched, and an OBS integration draft was written and kept out of the build (it has since been replaced by the OBS plugin in the plugin repository) — to be used once the real plugin loader exists. The requirements drawn from it are in `docs/agent-notes.md`.
- **Device pairing:** every connection must now carry either a valid `token` or the 6-digit PIN shown in the editor in `hello`; if both are missing or wrong, the server returns a `pairing_required` error and does not send `layout.full`. On a successful pairing the server issues a persistent token in `welcome.token`; the device stores it and never asks for the PIN again. New: `DeviceStore` (`%AppData%/MacroStation/devices.json`), `PairingService`, `/api/pairing/pin(/regenerate)`, `/api/devices` (GET/DELETE), and a "Pairing" panel in the editor (PIN + paired device list + remove). The test client (`wwwroot/index.html`) supports the PIN flow too (via prompt).
- The WebSocket protocol gained `profiles.list` (server→client, sent on hello) and `profile.change` (client→server) messages — a client can now change its own profile (the groundwork for the profile drawer).
- Stage 5 started: `client/` is now a Capacitor + React + TS app (Capacitor 8.5.2). Connect screen with IP entry, a main screen that draws the same grid as `@macro/renderer`, WebSocket reconnect (exponential backoff). The `android/` platform was added.
- Server skeleton: WebSocket protocol, JSON profile store, tray application, file logs, a temporary test client page (Stage 1).
- Live variables (`system.time`, `system.cpu`, `system.ram`, ...), page/profile switching, toggle widgets, `core.page`/`core.profile`/`core.open`/`core.delay` actions (Stage 2).
- `client/packages/renderer`: the shared grid/widget rendering engine — `Grid`, `WidgetView`, `ShadowHost`, `sanitizeWidgetCss`, `usePressGesture` (press/longPress/doubleTap/haptic) (Stage 3).
- `docs/color-bible.md`: the editor chrome color tokens and the widget swatch set.
- `server/editor`: the profile/page/widget editor (drag-resize with overlap prevention, style panel, CSS sanitize warnings, action editor), `/api/profiles` + `/api/actions` + `/api/variables/snapshot`, opened in a WebView2 window from the tray (Stage 4).

- Conditional (dynamic) widget style: `Widget.Dynamic` + `DynamicRuleEvaluator` (comparisons combined with AND/OR/XOR/NOT, data only — no code/eval), live push through `widget.state.style`.
- Categorized/searchable picker pattern (`PickerShell`), used in both the variable and icon pickers; the lucide-react icon library (1539 icons) was bundled.
- Icon size/position/color can be set; `core.open` was split into URL/Application, and application selection uses a native file dialog.
- Shortcut input now uses real key capture (no typing).
- An "Animation" option (None/Blink/Pulse) was added to widgets; like other style fields it can be made dynamic (for example, blink while cpu>80). Pure CSS `@keyframes` — no code/eval, the same security boundary holds.
- The dynamization window ("Build logic") was redesigned: each condition now reads like a "sentence" made of colored pills (variable/operator/AND-OR-XOR/result), consistent with the `docs/color-bible.md` tokens.
- The widget properties panel (Inspector) was reworked according to `docs/ui-guidelines.md`: flat surface + thin divider + small heading language (Appearance/Content/Actions) instead of cards inside cards, with the same order and look for every widget type. Color fields are now a single-row swatch+hex; alignment is an icon segmented control instead of a dropdown (lucide `AlignLeft/Center/Right`, `AlignVerticalJustify*`). Shared controls live in `panels/fields/controls.tsx` (`SectionLabel`, `ColorField`, `Seg`).

### Fixed
- `PUT`/`DELETE` success responses of the editor API are now `204 No Content` (they used to be `200` with an empty body, which caused a wrong "could not parse JSON" error in the client).
- Long press/double tap were never implemented in the test client (`wwwroot/index.html`); added.
- Widgets with no style no longer blend into the canvas (a default button color was added).
- The editor fetched the variable snapshot (`/api/variables/snapshot`) only once at startup, so the dynamic style preview stayed "frozen" (the saved rule was actually working correctly; the preview just did not reflect live CPU/RAM changes). It now refreshes automatically every 2 seconds.
- `Cache-Control: no-cache` was also added to `/api/*` responses — otherwise a GET right after a save could return stale data from the browser cache (this was the source of the "sometimes it saves, sometimes it doesn't" feeling).
- `widget.state.style`/`animation` were never applied in the test client (`wwwroot/index.html`) — dynamic color/animation pushes from the server were silently ignored.
- Editor HTML files are now served with `Cache-Control: no-cache` — previously WebView2/the browser kept showing the old `index.html` (and the old JS bundle it referenced) from cache even after the editor was rebuilt and the server restarted. Hashed `assets/*.js`/`*.css` files can still be cached.
- All emoji/symbol icons in the UI (✎, ⚡, ↑/↓, ×, →) were removed and replaced with `lucide-react` icons (Pencil, Zap, ChevronUp/Down, X, ArrowRight).
- In `ButtonContent`, the container's `flex-direction` was changed when the icon was above/below, which swapped the axes of the `justify-content`/`align-items` set for alignment (vertical alignment behaved like horizontal). Icon+text now sit in their own inner box (`.ms-content-inner`), so the outer box always applies alignment on the right axis.
